## 1. วิธีอ่าน

- **ความสำคัญ:** M = Must (ต้องมีใน MVP) · S = Should (ควรมี ทำหลัง MVP ได้) · C = Could (มีก็ดี) · Drop = ไม่ทำ — ✅ = ผู้ใช้ระบุเอง · ทั้งตารางยืนยันแล้ว 2026-11-26
- **สถานะ:** ⬜ ยังไม่ทำ · 🟨 กำลังทำ · ✅ เทียบเท่าแล้ว · ➖ ตัดออก
- **วิธีทดสอบเทียบ:** ระบบเดิมไม่ได้เปิดใช้งานแล้วและฐานข้อมูลไม่มีใบงาน → เทียบกับพฤติกรรมที่ถอดไว้ใน 02/04 (ทุกกฎมีตัวอย่าง input → output) และ layout จากโค้ดเดิม (หัวข้อ 6)

## 4. ตัวอย่างสูตรยอดรวมใบงาน (สำหรับตอบ Q13 — ระบบเดิมไม่มีการคำนวณ)

สองแบบที่เป็นไปได้ ให้ผู้ใช้เลือกหรือแก้ (ตัวอย่าง: ค่าขนส่ง 3,500 · ค่าผ่านท่า 500 · ค่าเสียเวลา 0 · จำนวนคืน 2 · ค่าแรงค้างคืน 300 · จำนวนคน 2 · ค่าแรงคน 400)

| แบบ | สูตร | ผลตัวอย่าง |
|---|---|---|
| A — ค่าแรงเป็นอัตราต่อหน่วย | ค่าขนส่ง + ค่าผ่านท่า + ค่าเสียเวลา + (จำนวนคืน × ค่าแรงค้างคืน) + (จำนวนคน × ค่าแรงคน) | 3,500 + 500 + 0 + 600 + 800 = **5,400.00** |
| B — ค่าแรงเป็นยอดรวมแล้ว | ค่าขนส่ง + ค่าผ่านท่า + ค่าเสียเวลา + ค่าแรงค้างคืน + ค่าแรงคน (จำนวนคืน/คนเป็นข้อมูลประกอบ) | 3,500 + 500 + 0 + 300 + 400 = **4,700.00** |

ถ้ามี VAT หรือหัก ณ ที่จ่าย: ระบุอัตรา, ฐานที่ใช้คิด (ทุกรายการหรือเฉพาะค่าขนส่ง) และวิธีปัดเศษ (ต่อรายการหรือท้ายบิล) — เงินคำนวณด้วยทศนิยมแบบตายตัว ไม่ใช้ float (skill.md หัวข้อ 6)

## 5. ขอบเขต MVP ที่เสนอ

**MVP = ทุกรายการ M (25 รายการ)** — ทำให้ใช้งานแทนระบบเดิมได้ครบ พร้อมแก้ข้อบกพร่องในหัวข้อ 3

| ลำดับโมดูล (ขั้นที่ 5) | ฟีเจอร์ | เหตุผลของลำดับ |
|---|---|---|
| 1. ผู้ใช้และสิทธิ์ | AUTH-01, 02, 05, 06, 07 | ทุกหน้าต้องใช้ |
| 2. ข้อมูลพื้นฐาน + ข้อมูลตั้งต้น | MD-01, 02, 03, 04, 08, GEN-05 | ใบงานต้องเลือกจากข้อมูลเหล่านี้ |

## 6. วิธีทดสอบเทียบ

1. **กฎธุรกิจ → unit test:** ทุกกฎใน 04 ที่มีตัวอย่าง input → output (เช่น เลขที่ใบงาน, ช่องบังคับ, ขอบเขตตัวเลข) เขียนเป็น test ด้วย Vitest
2. **Flow → E2E:** UC-01 ถึง UC-09 (02 หัวข้อ 7) เขียนด้วย Playwright บน Preview deployment + ทดสอบสิทธิ์ทุกบทบาท × ทุก route ตาม role matrix
3. **PDF → เทียบ layout:** สร้าง PDF จากใบงานทดสอบชุดเดียวกัน แล้วเทียบตำแหน่งช่องกับแม่แบบเดิม (`PrintWorkOrder.cshtml`) และภาพตัวอย่างถ้าผู้ใช้มี
4. **ทางเลือก (ขั้นที่ 7):** รันระบบเดิมบนเครื่องผู้ใช้กับฐานข้อมูลทดสอบแยก (ไม่ใช่ `TCRMIS` ที่ใช้ร่วมกับระบบอื่น) เพื่อเทียบหน้าจอแบบคู่กัน — ทำเมื่อผู้ใช้ต้องการเท่านั้น

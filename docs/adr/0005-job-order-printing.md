# ADR-0005: การพิมพ์ใบสั่งปฏิบัติงาน

- สถานะ: อนุมัติ — **เลือกทางเลือก A** หน้า HTML สำหรับพิมพ์ (D12 — 2026-11-27)
- วันที่: 2026-11-26

## บริบท

- ผู้ใช้ยืนยันให้มีหน้าพิมพ์ใบสั่งปฏิบัติงาน (WO-12, 2026-11-26)
- ระบบเดิม: Rotativa → `wkhtmltopdf.exe` แปลง HTML เป็น PDF ชื่อ `JobOrder_{เลขที่}.pdf` · โปรแกรมนี้เป็น .exe บน Windows ไม่มีการพัฒนาต่อแล้ว และวางไว้ใน `wwwroot` ให้ใครก็ดาวน์โหลดได้ (S8) · พิมพ์ใบงานที่มีรถหลายคันไม่ได้ (F4)
- ระบบใหม่บน Vercel รัน .exe ไม่ได้ · เนื้อหาเป็นภาษาไทย (ต้องตัดคำและวางสระ/วรรณยุกต์ถูก) · A4 แนวตั้ง

## ทางเลือก

| | A. หน้า HTML สำหรับพิมพ์ + พิมพ์จาก browser | B. สร้าง PDF ที่ server ด้วย headless Chromium | C. ไลบรารี PDF ใน JavaScript |
|---|---|---|---|
| วิธี | หน้า `/work-orders/[id]/print` จัดหน้าด้วย CSS `@page` A4 → เปิดกล่องพิมพ์ให้อัตโนมัติ → ผู้ใช้เลือกเครื่องพิมพ์ หรือ “บันทึกเป็น PDF” | Vercel Function รัน `puppeteer-core` (25.x) + `@sparticuz/chromium` (158) แปลงหน้าเดียวกันเป็นไฟล์ PDF | `@react-pdf/renderer` (4.9) วาด PDF ด้วย component ของตัวเอง |
| ผลลัพธ์ | พิมพ์ได้ทันที · ได้ไฟล์ PDF เมื่อเลือก “บันทึกเป็น PDF” (ชื่อไฟล์ `JobOrder_{เลขที่}` ตาม title ของหน้า) | กดแล้วได้ไฟล์ PDF ทันทีเหมือนระบบเดิม | ได้ไฟล์ PDF |
| ภาษาไทย | browser วาดเอง ถูกต้องที่สุด | ใช้ Chromium วาด ถูกต้อง (ต้องฝังฟอนต์ไทยเอง เพราะเครื่อง server ไม่มีฟอนต์ไทย) | ต้องฝังฟอนต์ และการตัดบรรทัดภาษาไทย (ไม่มีช่องว่างระหว่างคำ) ต้องจัดการเอง — เสี่ยงที่สุด |

| ข้อจำกัด | ผู้ใช้กดเพิ่ม 1 ขั้นในกล่องพิมพ์ · ควรปิด “หัวกระดาษและท้ายกระดาษ” ของ browser | แนบ PDF ไปกับอีเมล/เก็บไฟล์อัตโนมัติได้ในอนาคต | — |

## การตัดสินใจ (เสนอ)

**A สำหรับ MVP** — ง่าย, ภาษาไทยถูกต้องที่สุด, ไม่มีภาระบน server และใช้แนวทาง HTML เหมือนแม่แบบเดิม:

- route แยกไม่มีเมนู · CSS `@page { size: A4 portrait }` · ฟอนต์ Sarabun · layout ตาม Design 02 หัวข้อ 3.5 (รองรับรถหลายคัน)
- เรียกกล่องพิมพ์อัตโนมัติเมื่อหน้าโหลดเสร็จ และมีปุ่ม “พิมพ์” (ไม่แสดงตอนพิมพ์)
- title ของหน้า = `JobOrder_{เลขที่}` เพื่อให้ชื่อไฟล์ PDF ตรงกับระบบเดิม

ถ้าภายหลังต้องแนบ PDF อัตโนมัติ (เช่น ส่งอีเมลหรือใช้กับใบวางบิล) → เพิ่ม **B** เป็น endpoint แยกโดยใช้หน้า HTML เดียวกัน (เขียน ADR ใหม่) · ถ้าผู้ใช้ต้องการ “กดแล้วได้ไฟล์ PDF ทันที” ตั้งแต่ MVP → เลือก B แทน

## ผลที่ตามมา

- ทดสอบการพิมพ์ A4 บน Chrome และ Edge (ขอบกระดาษ, ตัดหน้า, สีหัวกล่อง)
- ไม่มีไฟล์ PDF เก็บบน server · ไม่ต้องใช้ Vercel Blob

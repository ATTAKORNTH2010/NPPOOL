# ADR-0007: การออกเลขที่ใบงาน

- สถานะ: อนุมัติ (D14 — 2026-11-27)
- วันที่: 2026-11-26

## บริบท

- รูปแบบเดิมต้องคงไว้: `NP` + ปี พ.ศ. 4 หลัก + เดือน 2 หลัก + running 4 หลัก เริ่มนับใหม่ทุกเดือน (BR-WO-01)
- ข้อบกพร่องเดิม (F1): หาเลขล่าสุดแล้ว +1 นอก transaction ไม่ล็อก ไม่มี unique → บันทึกพร้อมกันได้เลขซ้ำ, ลบใบล่าสุดแล้วเลขถูกใช้ซ้ำ, เกิน 9,999 แล้วซ้ำตลอดเดือน
- server ของ Vercel ใช้เวลา UTC — ถ้าคำนวณเดือนจากเวลา server ตรงๆ ใบงานช่วง 00:00–06:59 ของวันที่ 1 (เวลาไทย) จะได้เดือนก่อนหน้า

## ทางเลือก

1. หาเลขที่มากที่สุด + 1 (แบบเดิม) — ซ้ำเมื่อบันทึกพร้อมกัน
2. Postgres `SEQUENCE` ต่อเดือน — ต้องสร้าง sequence ใหม่ทุกเดือน และ sequence ไม่ย้อนกลับเมื่อ transaction ล้มเหลว → เลขข้าม
3. **ตารางตัวนับต่อเดือน** (`work_order_counters`) + `INSERT … ON CONFLICT DO UPDATE … RETURNING` ใน transaction เดียวกับการบันทึกใบงาน

## การตัดสินใจ (เสนอ)

ทางเลือก 3 (SQL ใน Design 03 หัวข้อ 5):

- `period` = ปี พ.ศ. + เดือน ของ**เวลาไทย (Asia/Bangkok)** ณ ตอนกดบันทึก เช่น `256911`
- เลขที่ = `NP` + `period` + running เติมศูนย์ให้ครบ 4 หลักใน TypeScript (`padStart`) — **ห้ามใช้ `lpad()` ของ Postgres** เพราะตัดข้อความที่ยาวเกิน
- unique constraint บน `work_order_no` · เลขที่ไม่ถูกนำกลับมาใช้ (ใบงานยกเลิกแล้วเลขยังอยู่)
- เกิน 9,999 ใบต่อเดือน → running ยาว 5 หลักต่อไปได้ (ค่าเริ่มต้นจนกว่าจะได้คำตอบ Q18)
- ระบบเดิมไม่มีใบงาน → เริ่มนับ 1 ในเดือนที่เปิดใช้ (ตั้งค่าเริ่มของตัวนับได้ถ้าต้องการต่อเลขจากที่อื่น)

## ผลที่ตามมา

- การบันทึกใบงานพร้อมกันในเดือนเดียวกันต่อคิวกันที่แถวตัวนับ (ไม่กี่มิลลิวินาที — เหมาะกับขนาดระบบนี้)
- transaction ล้มเหลว → ตัวนับย้อนกลับด้วย ไม่มีเลขหาย
- unit test: ใบแรก/ใบถัดไป/ข้ามเดือน/ข้ามปี/เวลา 00:30 ของวันที่ 1 ตามเวลาไทย · integration test: บันทึกพร้อมกันหลายใบต้องได้เลขไม่ซ้ำและเรียงต่อกัน

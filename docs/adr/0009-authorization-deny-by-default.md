# ADR-0009: การตรวจสิทธิ์แบบ deny by default

- สถานะ: อนุมัติ (D16 — 2026-11-27)
- วันที่: 2026-11-26

## บริบท

ระบบเดิมซ่อนเมนูตามบทบาท แต่บาง route ไม่ตรวจสิทธิ์เลย (หน้าสถานที่รับ-ส่ง — S3) และการลบ/บันทึกใบงานตรวจแค่ว่า login แล้ว (S4)

## ทางเลือก

1. ตรวจที่ `proxy.ts` (middleware เดิม) อย่างเดียว
2. ตรวจในแต่ละ page / Server Action อย่างเดียว
3. **ทั้งสองชั้น** + ตารางสิทธิ์กลางที่เดียว + test ทุก route × บทบาท

## การตัดสินใจ (เสนอ)

ทางเลือก 3:

- `proxy.ts`: ไม่มี session → ไป `/login` (ตรวจแบบเร็วจาก cookie — ไม่ใช่ด่านเดียว ไม่พึ่งเพื่อความปลอดภัย)
- `src/lib/permissions.ts`: ตารางสิทธิ์ตามบทบาท เช่น `workOrder.create`, `workOrder.view`, `workOrder.cancel`, `masterData.manage`, `user.manage` — แปลงจาก role matrix ที่ยืนยันแล้ว
- **ทุก page และทุก Server Action** เรียก `requirePermission(...)` ก่อนอ่าน/เขียนข้อมูล · ไม่ผ่าน → 403 / หน้าแจ้ง “ไม่มีสิทธิ์” (ไม่ใช่หน้า 404 แบบระบบเดิม)
- เมนูสร้างจากตารางสิทธิ์เดียวกัน (เมนูกับสิทธิ์ตรงกันเสมอ)
- ปุ่มที่ทำไม่ได้ไม่แสดง แต่ server ยังตรวจซ้ำทุกครั้ง

## ผลที่ตามมา

- E2E test วนทุกบทบาท × ทุก route และทุก action (รวมผู้ที่ไม่ได้ login) — test นี้ต้องผ่านก่อน deploy
- เพิ่ม route ใหม่ต้องระบุสิทธิ์เสมอ (ถ้าไม่ระบุ = ไม่มีใครเข้าได้)

# ADR-0012: Activity Log — การใช้งานของผู้ใช้แต่ละคนในแต่ละฟังก์ชัน

- สถานะ: ⏸ ทำตามคำขอผู้ใช้ 2026-11-27 (D31) — รอตรวจ
- วันที่: 2026-11-27

## บริบท

ผู้ใช้ขอ “เก็บ Activity Logs สำหรับ admin ดูการเข้าใช้งานของแต่ละ user ในแต่ละ function งาน” · ระบบเดิมไม่มี log การใช้งานเลย · ผู้ใช้มีไม่กี่คน (Admin / Maker / Accounting) แต่ข้อมูลเป็นข้อมูลธุรกิจและข้อมูลส่วนบุคคล (PDPA)

## ทางเลือก

1. log ของ Vercel (runtime logs) — เก็บสั้น ค้นหาไม่ได้ ผู้ดูแลระบบในบริษัทเปิดไม่ได้
2. **ตาราง `activity_logs` ในฐานข้อมูลเดียวกัน + หน้าดูสำหรับ Admin**
3. บริการภายนอก (analytics/observability) — ส่งข้อมูลผู้ใช้ออกนอกระบบ ไม่จำเป็นสำหรับขนาดนี้

## การตัดสินใจ

ทางเลือก 2

| เหตุการณ์ | เก็บอย่างไร | ฟังก์ชัน (`module`) |
|---|---|---|
| เข้าสู่ระบบ / ออกจากระบบ / เข้าสู่ระบบไม่สำเร็จ | hook ของ Better Auth (`src/lib/auth/hooks.ts`) · ไม่สำเร็จ: ผูกกับบัญชีเฉพาะเมื่อชื่อผู้ใช้ที่กรอกมีอยู่จริง ไม่เก็บชื่อที่ไม่มีในระบบ (กันรหัสผ่านที่พิมพ์ผิดช่อง) | `auth` |
| เปิดหน้า | `ActivityTracker` ใน layout ส่ง `sendBeacon` ไป `POST /api/activity` · server เลือกเฉพาะหน้าที่รู้จัก (`catalog.ts`) · หน้าเดิมซ้ำภายใน 5 นาทีในแท็บเดียวกันนับครั้งเดียว | ตามหน้า |
| บันทึก / แก้ไข / ยกเลิก / ลบ / เปิด-ปิดใช้งาน / จัดการผู้ใช้ | `runAction` บังคับให้ทุก Server Action ระบุ `activity` · เขียนหลังส่งผลให้ผู้ใช้แล้ว (`after()`) | ตามฟีเจอร์ |
| พิมพ์ใบสั่งปฏิบัติงาน | การเปิดหน้าพิมพ์ (action `print`) | `workOrders` |
| Export Excel | route `/api/work-orders/export` (จำนวนใบ + จำนวนเงื่อนไขค้นหา) | `workOrders` |

- คอลัมน์: เวลา, ผู้ใช้, ฟังก์ชัน, การกระทำ, รหัสรายการ, รายละเอียด (ไทย สั้น ๆ), path, IP (`x-real-ip` / `x-forwarded-for` ของ Vercel), user agent
- หน้า `/admin/activity` (สิทธิ์ `activity.view` = Admin): ตัวกรองผู้ใช้/ฟังก์ชัน/การกระทำ/ช่วงวันที่ · สรุปจำนวนครั้งต่อผู้ใช้ต่อฟังก์ชัน + ใช้งานล่าสุด · รายการใหม่→เก่า หน้าละ 50
- การเขียน log ล้มเหลวต้องไม่ทำให้งานของผู้ใช้ล้ม — จับ error แล้วเขียนแค่ชื่อ error ลง server log
- ไม่เก็บรหัสผ่าน และไม่เก็บค่าที่ผู้ใช้กรอกทั้งฟอร์ม — เก็บแค่สิ่งที่ระบุรายการได้ (เลขที่ใบงาน ชื่อข้อมูลพื้นฐาน บทบาท)

## ผลที่ตามมา

- ตารางโตตามการใช้งาน (ประมาณ 10 ผู้ใช้ × 200 เหตุการณ์/วัน ≈ 0.7 ล้านแถว/ปี) · **ยังไม่ลบ log อัตโนมัติ** — ต้องตกลงอายุการเก็บ (เช่น 1 ปี) และขนาดฐานข้อมูลของ Neon ก่อนขึ้นใช้งานจริง (ขั้นที่ 8)
- log เป็นข้อมูลส่วนบุคคล (IP, เวลาเข้าใช้) — เปิดดูได้เฉพาะ Admin และต้องระบุในนโยบายความเป็นส่วนตัวของบริษัท
- ไม่ใช่ audit trail แบบเก็บค่าก่อน/หลังการแก้ไข — ถ้าต้องการดูว่าแก้จากอะไรเป็นอะไร ต้องเพิ่มภายหลัง

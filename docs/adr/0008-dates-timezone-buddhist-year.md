# ADR-0008: วันเวลา, timezone และปี พ.ศ.

- สถานะ: เสนอ (พฤติกรรมตามค่าเริ่มต้น Q14 “เก็บวัน+เวลา” และ Q26 “แสดง พ.ศ.” ที่ยืนยันแล้ว)
- วันที่: 2026-11-26

## บริบท

- ระบบเดิมเก็บเวลาตามเครื่อง server (เวลาไทย) ไม่มี timezone · วันรับ/ส่งงานเป็น `date` ทำให้เวลาหาย (F3) · การแสดงปี พ.ศ./ค.ศ. ขึ้นกับการตั้งค่าเครื่อง (BR-UI-02)
- server บน Vercel ใช้เวลา UTC · ผู้ใช้ทั้งหมดอยู่ในประเทศไทย

## ทางเลือก

1. เก็บเวลาไทยแบบไม่มี timezone (เหมือนเดิม) — ผิดง่ายเมื่อ server เป็น UTC
2. **เก็บ `timestamptz` (UTC) แล้วแปลงเป็น Asia/Bangkok ทุกครั้งที่แสดงและทุกครั้งที่ใช้ “วัน/เดือน” ในกฎธุรกิจ**

## การตัดสินใจ (เสนอ)

- ทุกคอลัมน์วันเวลาเป็น `timestamptz`
- รวมการจัดรูปแบบและการแปลงไว้ที่ `src/lib/format.ts` ที่เดียว: `Intl.DateTimeFormat` locale `th-TH` ปฏิทินพุทธ (`calendar: 'buddhist'`) `timeZone: 'Asia/Bangkok'` → วันที่ `dd/MM/yyyy` ปี พ.ศ. · เวลา `HH:mm` 24 ชม.
- ช่องกรอกวันเวลา: ปฏิทินแสดงปี พ.ศ. · ค่าที่กรอกตีความเป็นเวลาไทย แล้วแปลงเป็น UTC ก่อนบันทึก
- ฐานข้อมูลเก็บปี ค.ศ. เสมอ (Postgres/JavaScript ใช้ปฏิทิน Gregorian) · ปี พ.ศ. เป็นแค่การแสดงผล ยกเว้นใน `work_order_no` ที่ใช้ ค.ศ. + 543 ตามกฎเดิม

## ผลที่ตามมา

- ห้ามใช้ `getMonth()` / `getFullYear()` ของเวลา server ตรงๆ ในกฎธุรกิจ — ใช้ฟังก์ชันใน `format.ts`
- unit test ขอบเวลา เช่น 2026-11-30 17:30 UTC = 01/12/2569 00:30 เวลาไทย (ต้องนับเป็นเดือนธันวาคม)
- ตรวจในขั้นที่ 4 ว่าปฏิทินของ shadcn/ui (react-day-picker 10) แสดงปี พ.ศ. อย่างไร — ถ้าไม่มีในตัว ปรับรูปแบบหัวปฏิทินเอง
